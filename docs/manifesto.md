📝 Project Manifesto: The Graph-to-Logic Compiler1. 프로젝트 정의 (Identity)목표: GraphRAG가 추출한 불확실한 '상관관계(Correlation)'를, 함수형 프로그래밍(FP)의 엄밀한 '인과관계(Causality)'로 변환하는 C++ 미들웨어 구축.핵심 가치: "LLM의 환각(Hallucination)을 컴파일 타임의 타입 에러(Type Error)로 제어한다."최종 형태: 단순한 번역기가 아닌, 논리적 오류를 스스로 가지치기(Pruning)하며 진화하는 '자기 조직화 시스템(Self-Organizing System)'.2. 핵심 철학 (Philosophy)위상의 대수적 타입화: 연결의 강도는 숫자가 아닌 **타입(Type)**이다.강한 연결 (Strong): std::pair<A, B> (Product Type) $\rightarrow$ 필연적 인과, 물리 법칙.약한 연결 (Weak): std::expected<B, Error> (Sum/Monad) $\rightarrow$ 사회적 합의, 불확실한 가능성.반사실적 검증 (Counterfactual Verification):단순히 "자주 같이 나오는가?"를 묻지 않고, **"A가 없으면 B도 존재할 수 없는가?"**를 NLI 모델에게 묻는다.이 '리트머스 시험'을 통과해야만 강한 연결로 승격(Promotion)된다.지도의 영토화: GraphRAG의 커뮤니티(Community)를 C++의 네임스페이스/모듈(Functor)로 격리하여, 논리적 범주가 다른 데이터의 무분별한 섞임을 차단한다.3. 시스템 아키텍처 (Architecture)단계컴포넌트역할 (Role)기술 스택1. 파싱Lexer / ParserGraphRAG의 JSON/GraphML을 읽어 AST(추상 구문 트리) 구축C++ Custom Parser2. 판별Logic Validator엣지의 논리적 필연성을 검증 (NLI, Counterfactual Check)ONNX Runtime (DeBERTa)3. 매핑Type Mapper검증 결과에 따라 C++ 타입(Strong vs Weak) 결정 및 코드 생성C++ Template Meta-programming4. 피드백Graph Gardener논리적 오류 발생 시 원본 그래프의 엣지를 삭제하거나 수정GraphDB (KuzuDB), Feedback Loop4. 개발 로드맵 (Wild Master's Roadmap)Phase 1: 뼈대 구축 (1~2개월)GraphRAG 없이 수동 입력 데이터를 처리하는 Code Generator 구현.목표: "나만의 DSL 파서 만들기" (참고: Crafting Interpreters)Phase 2: 뇌 이식 (3~4개월)NLI 모델 연동 및 반사실적 검증 로직 구현.나만의 커스텀 모나드(Axiom, Theory, Phenomenon) 정의.목표: "논리적 판단을 내리는 컴파일러 완성" (참고: Category Theory for Programmers)Phase 3: 신체 연결 (5~6개월)GraphDB 및 로봇 시뮬레이터(ROS 2) 연동.피드백 루프를 통한 자가 수정 기능 구현.Phase 4: 이론의 완성 (지속적)정보 물리학적 최적화 및 엔트로피 최소화 알고리즘 적용.5. 개인적 의미 (Significance)이 프로젝트는 **"야생의 석사 논문"**이다.컴퓨터공학, 로봇, 비선형 제어, 범주론을 하나로 꿰어내는 마스터 키 역할을 한다.단순 코더가 아닌, 시스템의 바닥(Bottom)부터 설계할 줄 아는 엔지니어임을 증명하는 포트폴리오다.
